# v0.4.0b9 - Feedback Refresh And Thermostat Presets

## Feedback Refresh

Mark the refresh timer as a Home Assistant event-loop callback. Previously HA
could dispatch it on an executor thread, where starting the background refresh
task caused pending-task errors. Keep the existing refresh cooldown, read-only
service calls and unload cancellation, and reject duplicate starts while a
refresh is in flight.

## Thermostat Presets

Ecobee exposes scheduled comfort presets and user-selected preset holds through
the same `preset_mode` attribute. Climado therefore uses the neutral effective
mode `thermostat_preset` instead of claiming every external preset is manual.
The card shows, for example, **Thermostat Home** and its reported target.

When Ecobee leaves Sleep before Climado's night-end time, Climado respects that
preset without forcing Sleep back on. Normal Climado control resumes at its
next night/day boundary. Explicit Climado overrides and Resume still take
precedence. Actual temperature holds remain `manual_hold`; changes to the Sleep
comfort temperature remain reflected without overwriting the comfort setting.

The existing `manual_hold_active`, `manual_hold_until` and `manual_hold_value`
attributes retain their compatibility meanings as an external thermostat hold.
Consumers distinguishing the origin should use effective mode/reason:
`thermostat_preset` for an external preset, `manual_hold` for a temperature hold.
No schedule, heating target, fan setting or fuel policy is changed by this release.
