# v0.4.0b11 - Acknowledge And Restore Automatic

Adds an explicit recovery action to the card and the targeted service
`climado.recover_fuel_automation` with `entry_id`.

Recovery requires a retained failure, enabled ULO heating control, fresh cloud
Heat and fuel reports, agreeing fresh local feedback when configured, and a
valid outdoor temperature. It rejects windows pauses/restoration, pending
thermostat requests and source handoffs. The card shows the blocking reason
while reports are unavailable, and bounded read-only Ecobee refreshes can
refresh old reports without reactivating Automatic.

Acknowledgement clears the retained system failure and enables Automatic using
the currently reported fuel, with a new 30-minute minimum source timer. It sends
no HVAC command and does not replay the failed request. Normal cycle completion,
confirmed Off, five-minute equipment rest and fuel confirmation requirements
continue to apply to later source changes.

The acknowledgement and activation are persisted separately; an interrupted or
failed activation leaves Automatic disabled and permits another explicit
recovery attempt. Existing failures are never acknowledged automatically.

Verification: 348 backend tests, 46 card tests and browser checks at 320, 390 and
1100 pixels passed. Coverage includes both sources, restart persistence, stale
and conflicting observations, unavailable equipment, windows/pending guards,
storage failures and service scoping. Recovery tests issue no HVAC commands.
